# Git & GitHub 원격 저장소 및 학습 정리

## 1. GitHub 기초 및 원격 저장소 (Remote Repository)
- **원격 저장소 (Remote Repository)**: 
  - 인터넷 상의 Git 저장소로, 여러 사람이 같은 코드를 공유하고 백업하며 협업의 기준점이 되는 공간입니다.
- **주요 명령어**:
  - `git remote add origin 원격주소`: 로컬 저장소를 원격 저장소(GitHub)와 연결합니다.
  - `git remote -v`: 현재 연결된 원격 저장소의 주소를 확인합니다.

---

## 2. git push와 git pull / fetch (동기화 및 실무 흐름)
- **git push**: 로컬 저장소의 커밋 이력을 원격 저장소(GitHub)로 업로드합니다.
- **git pull**: 원격 저장소의 변경 사항을 내려받아 로컬 코드에 반영(병합)합니다.
- **업로드와 다운로드의 특징**:
  - 업로드(`push`)와 다운로드(`fetch`)는 권한이 다를 수 있으며, 필요에 따라 원격 저장소 주소를 다르게 설정할 수도 있습니다.
  - 다른 사람의 작업물을 가져올 때는 주로 `fetch`보다 **`git pull`**을 더 많이 사용합니다.
- **💡 `git fetch`를 쓰는 경우 (추가 노트)**:
  - 다른 사람이 작업한 내용을 바로 내 코드에 합치지 않고, 어떤 변경 사항이 올라왔는지 **내용만 먼저 확인(조회)**하고 싶을 때 주로 사용합니다.

### 🛠️ 현업 협업 및 동기화 흐름
1. 수정 요청 사항이 발생하면 곧바로 `main` 브랜치에 반영하지 않고, `git push origin 브랜치이름`을 통해 별도의 브랜치를 생성하여 작업합니다.
2. GitHub 웹상에서 **Pull Request(PR)**를 생성하여 팀원들의 검토 및 컨펌을 거친 뒤 머지(Merge)를 진행합니다.
3. 머지가 완료된 후, VS Code 터미널에서 **`git pull origin main`** 명령어를 실행하여 로컬 환경을 최신 상태로 동기화합니다.

---

## 3. 협업 실습 핵심 개념 (Clone, Fork, PR)

### ① Clone vs Fork
- **Clone (클론)**: 
  - 원격 저장소를 그대로 내 로컬(컴퓨터)로 복사해 오는 것입니다.
  - 같은 저장소에 직접 `push` 권한이 있을 때 팀 내부 협업에 주로 사용합니다.
  - *실습 예시*: FastAPI 같은 오픈소스 코드를 내 컴퓨터로 클론해서 가져온 케이스
- **Fork (포크)**: 
  - 다른 사람의 저장소를 내 GitHub 계정으로 통째로 복사해 오는 것입니다.
  - 원본 저장소에 직접 `push` 권한이 없을 때 오픈소스에 기여하는 방식입니다.

### ② Pull Request (PR)
- 변경 사항을 원본 저장소에 반영해달라고 요청하는 기능입니다.
- 주요 단계:
  - 변경 내용 설명
  - 리뷰 요청
  - 병합 전 검증 단계



 # 📚 HTML 기초 & 웹 작동 원리

##  HTML 기초

###  HTML이란?
* **HTML (HyperText Markup Language)**
  * 웹 페이지의 구조를 정의하는 언어
  * 글의 제목, 문단, 이미지, 링크 같은 웹 페이지의 뼈대를 만드는 역할

### 웹과 HTML의 작동 흐름
* 서버가 HTML 문서를 만들어서 브라우저에 전달
* 브라우저는 HTML을 읽고 화면의 기본 구조를 그림
* **흐름**: 서버 $\rightarrow$ HTML 전달 $\rightarrow$ 브라우저 $\rightarrow$ 화면 구조 생성

---

## 3. HTML 기본 구조와 태그

### 3.1 기본 구조 특징
* HTML 문서는 항상 일정한 기본 틀을 가짐
* 태그(tag)들의 조합으로 구성
  * 태그는 `<태그이름>` 형태로 작성
  * 각 태그마다 요소의 의미와 역할을 가짐
  * 대부분의 태그는 **여는 태그**와 **닫는 태그**로 이루어짐
* **예시**:
  * `<h1>제목</h1>`
  * `<p>문단 내용</p>`

### 3.2 중첩 구조 (계층)
* 태그 안에 다른 태그가 들어갈 수 있으며, 이런 중첩 구조로 문서의 계층이 만들어짐
```html
<body>
  <h1>제목</h1>
  <p>내용</p>
</body>

<!DOCTYPE html>
<html>
<head>
  <title>My Page</title>
</head>
<body>
  Hello, HTML
</body>
</html>
